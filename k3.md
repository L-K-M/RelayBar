# K3 Review — RelayBar (macOS menu-bar SSH tunnel manager)

A thorough second pass over the fork at `L-K-M/RelayBar`, reviewing the code
as it exists on `main` (post-1.3.0, plus the status-item-ownership fork
changes). Reviewed: every file under `Sources/RelayBar/`, the test suite,
build/release scripts, task specs, and system specs.

Overall verdict: this is an unusually disciplined codebase. The process
management (launch generations, control-operation keying, bounded buffers,
owned-socket inode tracking, staged downloads) is genuinely careful, and the
security posture (argument allowlists, batch quoting, preview size caps, safe
Markdown policy) is better than most production Mac apps. What remains is
mostly: a handful of real behavioral bugs, some UX gaps where the app goes
quiet at the exact moment the user needs information, and a layer of delight
that high-value menu-bar apps have and this one doesn't yet.

Entries are numbered for tracking. Confidence = my confidence that the change
is correct, valuable, and safely implementable.

---

## 1. Bugs

### K3-01 — Clicking the menu-bar icon while the popover is open re-opens it instead of closing it (High confidence)

`RelayBarAppDelegate.togglePopover()` decides by reading `popover.isShown`
inside the button action. But the popover's behavior is `.transient`, so the
same click already closed it on mouse-down (a click outside the popover
window), and `popoverDidClose` has fired by the time the action runs on
mouse-up. `isShown` is therefore `false`, so the handler re-presents the
popover. Net effect: the icon cannot dismiss the popover; it flashes closed
and immediately reappears. Every other menu-bar app lets the icon toggle.

Fix: record the close timestamp in `popoverDidClose` and suppress re-present
when the toggle arrives within a short window (~300 ms) of an externally
caused close. All existing behavior (transient dismissal, re-launch re-open)
is preserved.

### K3-02 — Editing a running profile silently kills the tunnel (High confidence)

`TunnelStore.update(_:)` computes `wasActive`, calls `stop(tunnel)`, swaps the
profile in, and... never restarts it. Rename a live profile (or fix one
character of anything except the group tag) and its tunnel is dead afterward,
with no warning. The store even keeps `desiredTunnels` around, so the restart
path is one line. Fix: if the profile was desired before the update, start it
again after saving (the updated definition, fresh generation — the existing
launch pipeline handles everything else).

### K3-03 — Symlink-to-directory is unopenable in Remote Files (High confidence)

`ls -la` reports a symlinked directory as kind `.symbolicLink`, and
`RemoteFilesModel.activate` only navigates `.directory`. Double-clicking a
symlinked folder falls through to "download", and `sftp get` on a directory
symlink just fails. Symlinks to `.md`/images also lose previewability (that
check requires kind `.file`). Fix: when activating a symlink, resolve it
server-side by attempting a directory listing of the path with a trailing
slash (sftp resolves the link); if it lists, navigate; otherwise treat as
file for preview/download.

### K3-04 — "Back" from a directly opened file goes to the launcher instead of the parent folder (High confidence)

Task 034 made `ssh`-style direct file paths open in the browser/preview. But
`commitLoadedFile` pushes no navigation history, so `goBack()` finds an empty
stack and exits to the launcher — even though the toolbar already displays
the parent path. Back should load the parent directory. One small change in
the back path.

### K3-05 — `Include` directives in `~/.ssh/config` are silently ignored (High confidence)

`SSHConfigHostReader` scans only the top-level file for `Host` lines. Anyone
who organizes hosts with `Include ~/.ssh/config.d/*` (extremely common) gets
an incomplete server list in Remote Files with no explanation. Fix: follow
`Include` lines — relative patterns resolve against `~/.ssh` per the
ssh_config manual — with glob expansion, a recursion depth cap, and the
existing per-file size/host-count budgets.

### K3-06 — Quitting with active tunnels has no confirmation (High confidence)

⌘Q (or the footer's Quit) SIGTERMs every live tunnel instantly. One stray
keyboard chord and every connection drops. High-value menu-bar apps confirm:
"3 tunnels are running. Quit and stop them?" Fix: synchronous `NSAlert` in
`applicationShouldTerminate` when `runningCount > 0` (the Sparkle deferral
branch keeps precedence).

### K3-07 — The retry countdown never counts down (High confidence)

A retrying row prints "Retrying in 30s · <error>" — a static string frozen at
schedule time. It reads like the UI is stuck (arguably a perceived-stutter
bug). Fix: carry the retry deadline in `TunnelPhase.retrying` and render a
live countdown with `TimelineView`, which costs one text update per second
only while a retry is visible.

### K3-08 — The editor disables Save with zero explanation (High confidence)

`isValid` is a bare Bool over `builtTunnel != nil`. Bad port? Host with a
space? Conflicting listeners? Remote-SOCKS policy missing? Pending group
name? The user plays guessing games across a dozen fields. Fix: make the
builder return a failure reason and show the first one as inline caption
text near the action bar. Pure view-model logic, very testable.

### K3-09 — Downloaded files can land with loose final permissions (Medium confidence)

`SFTPRemoteFileService.securePartialPermissions` chmods the payload root to
0o600/0o700 *during polling*, but the last poll runs up to 250 ms before the
transfer finishes; nothing re-applies it after completion, so the moved file
keeps whatever sftp left (typically umask 0o644). Fix: one final chmod in the
success path before the move/replace. Cheap hardening that matches the
comment's stated intent.

## 2. General issues

### K3-10 — A stale editor draft can survive for weeks (Medium confidence)

The popover and its hosting controller are reused forever, so closing the
popover mid-edit keeps the half-filled editor; reopening RelayBar days later
lands you in that draft instead of the list. Either reset navigation to the
list on popover close, or treat it as a deliberate "draft" and say so. The
silent-surprise option is the one currently shipping.

### K3-11 — Cross-profile port conflicts fail late and cryptically (Medium confidence)

Two profiles listening on the same local port both start fine until ssh's
`-O forward` fails the second with `channel_setup_fwd_listener_tcpip:
cannot listen...`. The store knows every profile it runs; it can name the
offender up front: "localhost:8080 is already used by 'Hermes Dashboard'."
Preflight check against sibling desired profiles before launch.

### K3-12 — No "why did my tunnel die" surface outside the popover (High confidence)

When retries exhaust while the popover is closed, the only signal is the
menu-bar glyph quietly un-filling. The app should post a
`UNUserNotification` when a profile transitions to `.failed` from the retry
path (and only there — never for user stops). This is the difference between
"my tunnel dropped at 3 pm and I noticed at 6 pm" and knowing immediately.

### K3-13 — Main menu is minimal even by agent-app standards (Medium confidence)

The hand-rolled main menu has Quit, Edit, Window — but no Settings… (⌘,) and
no About. ⌘, is muscle memory for Mac users; wire it to open the popover on
the settings screen.

## 3. Performance

The codebase is mostly careful here (cached grouping, shared
`ByteCountFormatter`, off-main image/Markdown decoding, adaptive
progress-poll intervals, bounded everything). Remaining nits:

### K3-14 — Status-item image refresh schedules a Task per store publication (Low risk)

`observeTunnelActivity` fires a `Task` on every `objectWillChange` — every
retry tick, every phase change, every runtime-ports update — just to compare
one Int. Cheap, but trivially coalescible by observing `$phases` with
`removeDuplicates` on the derived count instead. Code-health more than perf.

### K3-15 — Retry-phase republishing re-renders the whole list body (Low risk)

Every `@Published` phase write re-evaluates `TunnelListView.body`, rebuilding
group headers and every row struct. At realistic profile counts (dozens) this
is invisible; if someone stores hundreds of profiles, the per-row
`Equatable`-style diffing would start to matter. No action needed now; noted
for the reorder/scale work.

### K3-16 — Preview of a multi-MB Markdown file re-renders off-main but lays out on main (Accepted)

MarkdownUI layout happens on the main actor when the view appears; a 2 MB
document can stutter once. Bounded by the 2 MB cap, one-shot, and cached
thereafter — acceptable; noted so nobody "optimizes" it by raising the cap.

## 4. Missing features

### K3-17 — Duplicate profile (High confidence, trivial)

The rule editor can duplicate a rule but the list can't duplicate a profile.
One menu item "Duplicate" → `store.add(tunnel.copyWithNewID())`. The single
most-requested affordance for tunnel managers (clone-then-tweak).

### K3-18 — Copy profile as an `ssh` command (High confidence)

Every profile is expressible as the `ssh -N -L/-D/-R … host` invocation the
Quick Add importer accepts (that round-trip is the tell). Offer "Copy SSH
Command" in the row menu: great for docs, tickets, sharing, and for users
who want to see what RelayBar actually runs. Pure formatter + tests.

### K3-19 — Import/export profiles as JSON (Medium confidence)

Backup, migration, and sharing all reduce to "export selected/all profiles
to JSON, import with dedupe by identity and validation through the existing
decode path". The Codable layer already exists; the work is panels + merge
semantics + errors.

### K3-20 — Plain-text / source-code preview in Remote Files (High confidence)

Remote Files previews images and Markdown only. The app already bundles
HighlighterSwift for Markdown code blocks — previewing `.txt`, `.json`,
`.log`, `.py`, `.swift`, `.yml`, etc. as read-only syntax-highlighted text
reuses that machinery behind the same size caps as Markdown. This is the
single biggest feature-shaped hole in Remote Files.

### K3-21 — Breadcrumb / enclosing-folder navigation in the browser (High confidence)

The toolbar shows the current path as inert text with only a one-step Back.
Clickable path components (or an "Enclosing Folder" ⌘↑ menu) is how Finder
users expect to move up three levels at once.

### K3-22 — Persist the last remote path per server (High confidence)

The server list has recents, but the path field resets to empty every time
the window is recreated. Remembering the last opened path per connection
(and pre-filling it) removes the most repetitive typing in the app.

### K3-23 — Multiple concurrent transfers / a transfer queue (Medium confidence)

`download` is one-at-a-time (`guard !isTransferRunning`). A small queue
(even just N=2–3 parallel, or FIFO) with per-transfer rows would match user
expectations set by every FTP client ever. Moderate model surgery.

### K3-24 — Sort options in the file list (Medium confidence)

Fixed "folders first, then name" today. Name/size/date ascending-descending
toggle in a toolbar menu is expected table behavior.

### K3-25 — Keyboard navigation inside the popover (Medium confidence)

The list is mouse-only: no arrow-key selection, no space/return to toggle, no
⌘N for new profile. Menu-bar apps with lists (1Password, Tailscale) all
support this; it's the difference between "nice" and "fast".

### K3-26 — Search/filter field when the profile list is long (Medium confidence)

Groups help organization; a filter helps finding. One text field filtering
by name/host/group.

### K3-27 — Auto-start profiles at launch (High confidence)

The Launch-at-Login caption explicitly promises "saved profiles stay
stopped" — correct as a default, but a per-profile "Start automatically" (or
global "resume profiles that were running at quit") is the most natural next
setting. The store can persist an `autoStart` flag with the existing
validation-on-decode pattern.

### K3-28 — Global hotkey to open the popover (Lower confidence)

Carbon `RegisterEventHotKey` still works without permissions. Delightful for
power users; needs a settings UI and conflict handling. Nice-to-have.

### K3-29 — App Shortcuts / URL scheme for start/stop (Lower confidence)

`relaybar://start/<name>` or an App Intents surface enables Alfred, Raycast,
Stream Deck, and Shortcuts.app. Bigger surface area; defer unless there's
demand.

## 5. Visual issues & layout

### K3-30 — The row ellipsis menu button is visually orphaned (High confidence)

Every other icon button (settings, add, open-in-browser) sits in a tinted
circle; the per-row `⋯` menu is a bare glyph with no background, no hover
state, and a slightly smaller hit target (25×25 vs 28×28). Give it the same
subtle circle treatment (at least on hover) for consistency.

### K3-31 — No hover feedback on any custom button (High confidence)

`.buttonStyle(.plain)` + static background = the app feels inert to the
mouse. A tiny shared `CircleIconButton` style with hover darkening (via
`onHover` or a proper `ButtonStyle`) would make the whole popover feel alive.
Big perceived-quality win for very little code.

### K3-32 — The status dot is static while connecting (Medium confidence)

During starting/retrying the 8-pt dot is flat orange; the toggle shows a
spinner but the eye lands on the dot first. A gentle opacity pulse
(`withAnimation(.repeatForever)`) communicates "working" instantly.

### K3-33 — Error text is truncated with no way to read it (Medium confidence)

Row error lines are `lineLimit(1)` with no tooltip. Add `.help(message)` (or
an expandable error) so "SSH could not install a forwarding rule (status
255)" is actually readable when it matters.

### K3-34 — Group headers could carry a rollup status and count (Low confidence)

A tiny filled-dot/number beside the group name ("2 of 3 running") would make
groups scannable at a glance. Pure polish.

### K3-35 — The popover background is flat (Low confidence)

`windowBackgroundColor` + card fill is fine, but a `NSVisualEffectView`
material under the cards would make it feel like a native menu-bar surface
(Control Center, 1Password). Subtle; try behind a flag first.

## 6. Delightful / novel ideas

### K3-36 — Clipboard-aware Quick Add (High confidence)

When the editor opens and the pasteboard holds a plausible `ssh … -L/-D/-R`
command, show a small chip: "Import command from clipboard ⇧⌘V". One click,
form fills. This is the kind of thing users screenshot and share.

### K3-37 — Active-count badge on the menu-bar icon (High confidence)

The glyph already flips filled/outline for any/none. Compositing a tiny
count badge (or dot-per-count up to 3) tells "how many" without opening the
popover. Cheap `NSImage` composition next to the existing drawing code.

### K3-38 — Connection uptime in the row (Medium confidence)

"via user@host" is static; "up 2h 13m · via user@host" for running profiles
is alive. Store the connect instant when the phase flips to `.running` and
render with `Text(timerInterval:)`-style ticking text. Small, warm, useful.

### K3-39 — "Test connection" in the editor (Medium confidence)

A quiet button that runs a bounded `ssh -o BatchMode=yes … -T host` probe and
reports reachable/auth-ok/unreachable before you save. Turns configuration
from guess-and-check into immediate feedback.

### K3-40 — Import from ssh_config snippets (Lower confidence)

The Quick Add parser accepts `ssh` command lines; ssh_config blocks
(`Host x` + `LocalForward …`) are the other place tunnel commands live.
Parsing those into profiles would be a genuinely novel importer. Bigger
grammar; defer.

## 7. Recommended implementation order

Highest confidence-to-effort ratio first. Each item is independently
shippable.

1. **K3-01** popover toggle fix (tiny, daily papercut)
2. **K3-02** restart profile after edit (tiny, prevents silent downtime)
3. **K3-04** Back-to-parent from direct file (tiny)
4. **K3-17** duplicate profile (tiny)
5. **K3-07** live retry countdown (small)
6. **K3-06** quit confirmation (small)
7. **K3-18** copy SSH command (small, pure function)
8. **K3-05** ssh_config `Include` support (medium, pure parser + tests)
9. **K3-08** editor validation reasons (medium)
10. **K3-22** persist last remote path (small)
11. **K3-36** clipboard-aware Quick Add (small-medium)
12. **K3-09** final download chmod (tiny)
13. **K3-30/31/33** button consistency + hover + error tooltips (small,
    one "visual polish" batch)
14. **K3-12** failure notification (medium, permission flow)
15. **K3-03** symlink navigation (medium, remote semantics)
16. **K3-20** text/code preview (larger; the flagship feature)

Deferred (needs design discussion or larger surgery): K3-19 import/export,
K3-21 breadcrumbs, K3-23 transfer queue, K3-24 sort options, K3-25 keyboard
nav, K3-26 filter, K3-27 auto-start, K3-28 hotkey, K3-29 Shortcuts, K3-34/35
group rollup & material background, K3-38 uptime, K3-39 test connection,
K3-40 config import, K3-10 stale draft decision, K3-11 conflict preflight,
K3-13 menu extras, K3-14/15 coalescing.
